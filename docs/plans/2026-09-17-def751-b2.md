## Commit 1 — herkomst en kandidaatbinding

### Contract (`src/domain/categorie_herkomst.py`, puur)
- Eén onveranderlijk keuze-event: `value` (exact een van de elf `OPSLAGCATEGORIEEN` of `null`), `origin` (`manual`/`editor`/`model`/`import`/`default`), `actor` + `actor_source` (alleen bij `manual`/`editor`; `typed_name` of `session_user` — een opgegeven naam, geen authenticatie), `recorded_at`, `record_version_at_write` (informatief, nooit bijgewerkt), `candidate` (term + drie canonieke contexten + vingerafdruk), `binding` (`generation_candidate` met `generation_id` en tekstvingerafdruk, of `term_context`), `reasoning`/`scores` (model).
- Status bij lezen (`bepaal_keuzestatus`), niets schuift mee: `manual_confirmed` (actor bekend), `manual_unattributed`, `model_suggestion`, `imported`, `imported_missing`, `default`, `unknown_origin` (kolomwaarde zonder event — historisch bewijs ontbreekt, nooit achteraf default/handmatig), `absent` (geen waarde, geen event), `invalid`, `stale`.
- Stale = term/context-vingerafdruk wijkt af óf de opgeslagen kolomwaarde wijkt af van het event. Een tekstwijziging maakt de keuze niet stale, maar bij een generatiegebonden keuze wordt `text_unchanged: false` zichtbaar (de keuze gold voor de gegenereerde tekst; geen herbevestiging). Een kolom die zonder event wordt teruggeschreven naar de oude waarde maakt het oude event niet "opnieuw actueel" — het event is nooit gewijzigd en de historie meldt niets; alleen de afgeleide status klopt weer. Dit is de grens van de binding (term/context, niet de bedoeling achter een tekst) en staat zo in de UI-tekst.
- Grens voor aangeleverde invoer (`lees_keuze_invoer`): options/metadata/payload leveren alleen `origin` ∈ {manual, model} + reasoning/scores; actor/tijd/status worden genegeerd; `editor`/`import`/`default` zijn daar ongeldig (fail-closed).

### Opslag (`database/definitie_crud.py`, `database/models.py`)
- `update_definitie(updates={"categorie": …, "category_choice": {...}})`: structurele sleutel naar het `source_evidence`-patroon. `_geldige_keuze_invoer` weigert vóór mutatie: herkomst buiten editor/manual, geen `categorie` in dezelfde update, actor ≠ `updated_by`, onbekende actorbron, ongeldige waarde (niet omgezet). Onder de lock: nieuw event met de resulterende term/context als kandidaat, vorige event exact naar `category_choice_history` (`event`, `superseded_at`, `superseded_on_version`), in dezelfde UPDATE als de kolom; versieconflict → `False`, niets geschreven. Bronbewijs, CON-02-historie, prompt en vreemde sleutels in `generation_prompt_data` blijven staan.
- Readback: `DefinitieRecord.get_category_choice/_history/_status`; servicelaag zet `metadata["category_choice"]`, `category_choice_status`, `category_choice_history` (leessleutels) — de invoersleutel is `category_choice_input`, zodat openen + opslaan nooit een tweede event maakt.

### Routes
- Generatie: handler → `options["category_choice"] = {origin manual|model, reasoning, scores}` (geen actor: de generator-tab kent geen identiteit) → orchestrator `_create_definition_object` → `metadata["category_choice_input"]` via `lees_keuze_invoer` → `_generatieregistratie_voor_record` bouwt het event generatiegebonden (`generation_id`, tekstvingerafdruk), actor altijd `null`. Repositorydefault "proces" (nog aanwezig in commit 1) wordt als bewezen `default`-event vastgelegd; zonder invoer en zonder default géén event (`unknown_origin`).
- Editor: alleen een werkelijk gewijzigde categorie bij Opslaan is een keuze (`editor`) met de bestaande `_handelende_gebruiker()` (sessie-`user` → `session_user`, anders getypte reviewer-naam → `typed_name`); zonder identiteit ongeattribueerd. `_apply_updates` kopieert de metadata zodat de invoersleutel niet in het sessieobject achterblijft. Statusregel onder de selectbox (`beschrijf_keuzestatus`).
- Toepassen (post-generatie): `CategoryService.update_category_v2(user=None)` → `manual`-event zonder actor; het gefabriceerde `"web_user"` is verwijderd (renderer, workflow-default, legacy `update_category`); bestaande test `test_update_category_success` aangepast op die productvereiste.
- Voorstel/override-state: termwissel en contextwissel (`classification_basis`) wissen voorstel én `manual_ontological_category`; "Aanpassen?" terug op leeg trekt de override in; "Wis velden" wist ook de basis.
