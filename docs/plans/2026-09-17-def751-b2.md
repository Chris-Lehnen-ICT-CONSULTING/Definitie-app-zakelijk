## Commit 1 — herkomst en kandidaatbinding

### Contract (`src/domain/categorie_herkomst.py`, puur)
- Eén onveranderlijk keuze-event: `value` (exact een van de elf `OPSLAGCATEGORIEEN` of `null`), `origin` (`manual`/`editor`/`model`/`import`/`default`), `actor` + `actor_source` (alleen bij `manual`/`editor`; `typed_name` of `session_user` — een opgegeven naam, geen authenticatie), `recorded_at`, `record_version_at_write` (informatief, nooit bijgewerkt), `candidate` (term + drie canonieke contexten + vingerafdruk), `binding` (`generation_candidate` met `generation_id` en tekstvingerafdruk, of `term_context`), `reasoning`/`scores` (model).
- Status bij lezen (`bepaal_keuzestatus`), niets schuift mee: `manual_confirmed` (actor bekend), `manual_unattributed`, `model_suggestion`, `imported`, `imported_missing`, `default`, `unknown_origin` (kolomwaarde zonder event — historisch bewijs ontbreekt, nooit achteraf default/handmatig), `absent` (geen waarde, geen event), `invalid`, `stale`.
- Stale = term/context-vingerafdruk wijkt af óf de opgeslagen kolomwaarde wijkt af van het event. Een tekstwijziging maakt de keuze niet stale, maar bij een generatiegebonden keuze wordt `text_unchanged: false` zichtbaar (de keuze gold voor de gegenereerde tekst; geen herbevestiging). Een kolom die zonder event wordt teruggeschreven naar de oude waarde maakt het oude event niet "opnieuw actueel" — het event is nooit gewijzigd en de historie meldt niets; alleen de afgeleide status klopt weer. Dit is de grens van de binding (term/context, niet de bedoeling achter een tekst) en staat zo in de UI-tekst.
- Grens voor aangeleverde invoer (`lees_keuze_invoer`): options/metadata/payload leveren alleen `origin` ∈ {manual, model} + reasoning/scores; actor/tijd/status worden genegeerd; `editor`/`import`/`default` zijn daar ongeldig (fail-closed).

### Opslag (`database/definitie_crud.py`, `database/models.py`)
- `update_definitie(updates={"categorie": …, "category_choice": {...}})`: structurele sleutel naar het `source_evidence`-patroon. `_geldige_keuze_invoer` weigert vóór mutatie: herkomst buiten editor/manual, geen `categorie` in dezelfde update, actor ≠ `updated_by`, onbekende actorbron, ongeldige waarde (niet omgezet). Onder de lock: nieuw event met de resulterende term/context als kandidaat, vorige event exact naar `category_choice_history` (`event`, `superseded_at`, `superseded_on_version`), in dezelfde UPDATE als de kolom; versieconflict → `False`, niets geschreven. Bronbewijs, CON-02-historie, prompt en vreemde sleutels in `generation_prompt_data` blijven staan.
- Readback: `DefinitieRecord.get_category_choice/_history/_status`; servicelaag zet `metadata["category_choice"]`, `category_choice_status`, `category_choice_history` (leessleutels) — de invoersleutel is `category_choice_input`, zodat openen + opslaan nooit een tweede event maakt.

### Routes
- Generatie: handler → `options["category_choice"] = {origin manual|model, reasoning, scores}` (geen actor: de generator-tab kent geen identiteit) → orchestrator `_create_definition_object` → `metadata["category_choice_input"]` via `lees_keuze_invoer` → `_generatieregistratie_voor_record` bouwt het event generatiegebonden (`generation_id`, tekstvingerafdruk), actor altijd `null`. Repositorydefault "proces" (nog aanwezig in commit 1) wordt als bewezen `default`-event vastgelegd; zonder invoer en zonder default géén event (`unknown_origin`).
- Editor: alleen een werkelijk gewijzigde categorie bij Opslaan is een keuze (`editor`) met de bestaande `_handelende_gebruiker()` (sessie-`user` → `session_user`, anders getypte reviewer-naam → `typed_name`); zonder identiteit ongeattribueerd. `_apply_updates` kopieert de metadata zodat de invoersleutel niet in het sessieobject achterblijft. Statusregel onder de selectbox (`beschrijf_keuzestatus`).
- Toepassen (post-generatie): `CategoryService.update_category_v2(user=None)` → `manual`-event zonder actor; het gefabriceerde `"web_user"` is verwijderd (renderer, workflow-default, legacy `update_category`); bestaande test `test_update_category_success` aangepast op die productvereiste.
- Voorstel/override-state: termwissel en contextwissel (`classification_basis`) wissen voorstel én `manual_ontological_category`; "Aanpassen?" terug op leeg trekt de override in; "Wis velden" wist ook de basis.

## Correctieronde 1 (Codex-review op commit 1, vijf bevestigde bevindingen — alle FIX NU)

1. **Verouderde keuze herleefde door terugzetten.** Naast het onveranderlijke event bewaart de persistentielaag nu een persistente toepassingsstaat `category_choice_state` (`current`, `invalidated_on_version`/`_at`/`_reason`, `text_changed`/`_on_version`/`_at`). Elke `update_definitie` die term, context of categorie *werkelijk* wijzigt (genormaliseerde vergelijking; een editor-opslaan met gelijke waarden raakt niets) zet `current=false` in dezelfde UPDATE; `bepaal_keuzestatus` leest de staat als leidend, de vingerafdrukken blijven vangnet. Terugzetten herstelt niets; alleen `record_category_choice` maakt een nieuw event met een verse staat (het vorige event mét zijn staat naar de historie). Bewijs: `test_verouderde_keuze_herleeft_niet_door_terugzetten[term|context|categorie]`, `test_invalidatie_landt_in_dezelfde_transactie_als_de_wijziging` (auditfout rolt ook de invalidatie terug).
2. **Import/metadata fabriceerden menselijke herkomst.** Menselijke herkomst (`editor`/`manual` met actor) ontstaat uitsluitend via het expliciete commando `DefinitieCRUD.record_category_choice` (facade + `DefinitionRepository.save_met_categoriekeuze` + `DefinitionEditService.save_definition(categoriekeuze=…)` + `CategoryService.update_category_v2`). Het generieke `updates`-dict weigert `category_choice` (ValueError); `Definition.metadata` draagt voor een bestaand record geen keuze meer en voor een nieuw record alleen herkomst manual/model zonder actor (`lees_keuze_invoer`). `create_definitie(categoriekeuze=…)` bouwt het event zelf en zet een event uit aangeleverde JSON (JSON-import, ruwe payload) als onbevestigde invoer onder `category_choice_imported`; een ruwe `generation_prompt_data`-update kan de beheerde sleutels (`CATEGORY_CHOICE_OWNED_KEYS`) niet vervangen. Geen account-/RBAC-laag: de grens is de route, niet een aangeleverd veld. Bewijs: `test_json_import_met_manual_confirmed_event_wordt_niet_als_bevestigd_gelezen` (echte `import_from_json`, readback `imported`, geen naam/tijd in de caption, inhoud bewaard), `test_ruwe_generation_prompt_data_update_kan_geen_keuze_fabriceren`, `test_metadata_en_updates_kunnen_geen_toegeschreven_keuze_maken`, `test_generiek_updates_dict_kan_geen_keuze_dragen`, `test_commando_accepteert_alleen_menselijke_herkomst`.
3. **Actieve routes zonder atomaire versiecontrole.** `record_category_choice` eist `expected_version` en zet die als `WHERE version_number = ?` op de uiteindelijke UPDATE; `update_category_v2`/`update_category`/`execute_category_change_workflow` dragen `expected_version` (renderer: `saved_record.version_number`); de editor geeft `updates["version_number"]` door en `_definition_to_updates` neemt `metadata["version_number"]` (gezet bij laden) altijd mee — ook een gewone `update` is nu een optimistic lock. Conflict → `False`/`RepositoryError`, geen succes, geen terugschrijven. Bewijs (geïnjecteerde concurrente update tussen voorcontrole en schrijven): `test_toepassen_route_weigert_bij_gelijktijdige_wijziging`, `test_editor_route_weigert_bij_gelijktijdige_wijziging`, `test_save_met_categoriekeuze_eist_de_versie_en_weigert_een_verouderd_object`, `test_gewone_update_draagt_de_geladen_versie_als_optimistic_lock`.
4. **Widgetstaat `manual_category_override` bleef staan.** `_wis_classificatie` wist ook de widgetsleutel, vóór het renderen (begripinvoer/contextbasis). Bewijs met echte Streamlit-controls (`tests/unit/ui/test_def751_categorie_apptest.py`, subprocess-driver achter de offline-gate, fake classifier): TYPE kiezen → termwissel → widget én effectieve override leeg; opnieuw TYPE → contextwissel DJI→OM → leeg; TYPE → "Aanpassen?" leeg → override ingetrokken, voorstel blijft. De RED-vorm van dit scenario is de reviewproef; de eigen test is ná de fix geschreven en groen.
5. **Tekstwijziging na editorkeuze onzichtbaar.** Elk event (ook editor/toepassen) draagt nu de tekstvingerafdruk; een werkelijke tekstwijziging zet `text_changed` (+ versie) blijvend in de staat, ook na terugzetten. Status en caption (`beschrijf_keuzestatus`) tonen: "Let op: de tekst is sindsdien gewijzigd (versie N); de keuze gold voor de tekst van toen en bevestigt de huidige tekst niet." Geen herbevestiging. Bewijs: `test_tekstwijziging_na_editorkeuze_is_zichtbaar_en_herleeft_niet`, `test_save_met_categoriekeuze_is_het_commando_voor_de_editorroute`.

Bijgewerkte bestaande tests (gewijzigde productvereiste, geen maskering): `test_category_service*.py` (commando + verplichte versie, geen `web_user`), `test_def751_categoriekeuze_opslag.py`/`_transport.py`/`_ui.py` (commando-API).
